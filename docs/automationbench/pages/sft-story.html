The 4B SFT Story
Supervised fine-tuning · result of 13 Nov 2026 · updated 24 Nov 2026

Teaching a 4B model to do office work by showing it how

We wanted Qwen3.5-4B to solve more AutomationBench office tasks (emails, sheets, CRM, Slack) without reinforcement learning. Supervised fine-tuning (SFT) is the simplest way: show the model correct worked examples and let it learn to copy them. The first try made the model worse. The second try, with a thinking teacher and strictly checked data, worked.

Lesson 1

A small model copies the shape, not just the answers

The answers were correct, but the examples showed actions with no reasoning. The 4B learned to act without thinking. With thinking switched off, the text it writes before each action is its only place to plan.

4

What the trained model then did

On a held-back task (flag departments over their office-supply budget, using a spend tab, a budget tab and a policy tab), the untrained 4B read all three tabs, planned out loud and got it right. After 5 passes, the trained model wrote no text, never opened the policy tab, alerted the one department that was exempt, missed the three that were over, and signed off with the copied "Done:" line.

5

Digging deeper: four more lessons

Lesson 2

Don't convert examples after the fact

Claude often did several independent actions at once (419 of its 811 action turns). Our conversion split them into one action per turn, so the 4B lost that too. Generate examples directly in the 4B's own format instead.

verified
Lesson 3

Every word we train on gets copied

Where we filled in a placeholder ending ("Done: …"), the model learned to say it. 37 of 99 endings written by the untrained 4B also broke the system prompt's rules. Only train on text we actually want the model to say.

verified
Lesson 4

Check the exact file you train on

The training framework re-wrote every example with its keys sorted alphabetically, so training prompts no longer matched what the model sees in a test. Our format check had looked at the data one step earlier and missed it.

verified
Lesson 5

"Correct" is not the same as "teaches the right thing"

Our checks asked whether each example was correct. None asked whether it showed the behaviour we want the model to learn. Every future check asks both.

6

Are the training tasks themselves right?

24 tasks never got a verified solution. We studied each one by hand and proved every one can be solved. But some have a problem in the task itself: the request can be read two ways and the checker accepts only one, or the checker is simply wrong.

9fine; the model just missed a policy sheet or a note
12ambiguous: the checker accepts only one valid reading
3broken: the checker or a tool has a bug

Example of a broken task: the request asks for conversion rates with two decimals ("1.50%"), but the checker looks for "1.5%", and its text cleaner only tidies "1.0%"-style numbers. A model that follows the request exactly fails. verified

All 204 tasks: doing nothing passes none of them. The untrained 4B never solves 119, sometimes solves 82, always solves 3. verified

Lesson 6

Fix the tasks, don't skip them

A bad task teaches a bad habit to every method that uses it later (SFT, DPO and beyond). So every flagged task gets a proper fix. Chapter 9 shows how that was done.

7

What published research told us

We read the research on training small agent models from examples. No paper matches our exact setup, so these guide the design rather than promise a result.

Reasoning text in the examples matters

Agent models trained with the reasoning kept generalise better to new tasks than those trained on actions alone.

AgentBank · Lù & Reddy 2026 reported

Make examples in the student's own world

Strong pipelines run the teacher inside the same environment and format as the student, then keep only runs that pass an outcome check.

APIGen-MT · SWE-Gym · SWE-smith reported

Small students like short, simple reasoning

Small models learn worse from long, expert reasoning than from shorter, simpler explanations.

Li et al. 2025, "Small Models Struggle to Learn from Strong Reasoners" reported

Don't give the teacher hints

When the teacher sees information the student won't have, the student learns shortcuts it can't reproduce. Hints belong with the grader, not the teacher.

Kaur et al. 2026 (maths, indirect evidence) reported

Don't train on mistakes

In one study, leaving failed steps out of the training target worked better than training on them. Earlier work found mixed results, so we simply keep failed actions out.

AgentRefine reported

Agent-only data can hurt general skill

Training only on agent examples has been reported to damage general ability, which fits the drop we saw on guard10.

AgentTuning reported

Tools we evaluated: NeMo Data Designer

NVIDIA's open-source generator runs a teacher model against tools and records each run. It needs API access to the teacher, so we build the same loop on our own replay tool, with our stricter checker.

A new plan: a thinking teacher from the same family

The new teacher is Qwen3.5-397B-A17B, a much larger model from the 4B's own family, called through OpenRouter with one provider (Alibaba) pinned. Thinking is switched on, so the teacher's reasoning is recorded inside <think> tags. That is exactly where the 4B does its own thinking, so the 4B can learn the reasoning, not just the actions (Lesson 1). The teacher runs inside the same loop, tools and format the 4B uses in a test (Lesson 2).

Step 1: fix the tasks and prove they can be solved

A task counts as correct when a solution replays at 1.0 (full score), doing nothing fails, no check contradicts the request or the data, no tool bug blocks the right action, and no wrong answer passes. Ali set this standard on 12 Nov.

38defect tasks fixed (70 edits in 15 files), approved by Ali
0 / 204tasks pass if the model does nothing
24 / 24earlier hand proofs still score 1.0

The fixed tasks became the pinned environment 86994309. Every replay, baseline, training row and evaluation in Part two uses it. Some fixes were in shared code (for example the number cleaner that turns "1.50%" and "1.5%" into the same value), which also touches some test120 tasks. That is why the untrained baseline was measured again on the fixed environment. verified

"The old wrong solution now fails" does not prove a fixed task can be solved. So for each fixed task we required a correct solution that replays at 1.0. 11 fixed tasks lacked one at first. 6 were then proven by teacher runs that scored 1.0, and 5 by hand-written proofs (kept as proof only, never as training data). Two more never-solved tasks got hand proofs on 13 Nov. No fix made a task unsolvable. verified

Problem solved on the way

Why the teacher's test run kept crashing

The 397B test120 run was killed twice by its own 10 GB memory limit, at the same 15 tasks. Our first guess, that the runner keeps every attempt in memory, was wrong. The real cause was one task, sales.docusign_bulk_nda_sender. The benchmark's guard checks create one scoring run for each pair of (data row × action the agent took). With about 45 envelopes and 45 contact updates that is about 20,000 scoring runs in one attempt, each loading a 2.7 MB view of the data. One attempt peaked at 9.3 to 10.2 GB. The fix was to run the 14 light tasks in small groups and that one task alone with a 16 GB limit. The reference then finished: 120 tasks, 240 attempts, 0 errors. from record

11

Step 3: the teacher writes examples, code checks every one

The 397B tried every one of the 204 training tasks, up to 3 times each, in rounds. An attempt can only enter the training data if it passes every automatic check below (the validate_row gates). Passing the benchmark is necessary but not enough.

  • Replay to 1.0: replayed in the benchmark on the fixed environment, it scores full marks with every check passing.
  • Same results: every tool result in the example is byte for byte what the replay returns.
  • Reasoning on every turn: each turn the 4B is trained on has thinking before its actions.
  • Grounding: every number in written text appears earlier in the conversation or is worked out on the page.
  • Zero tool errors: no failed calls in trained turns.
  • Reply rule: the final reply follows the system prompt, which says to list only items acted on and never name skipped ones.
  • No tooling words: nothing that mentions our own harness.
  • No loops: no identical call made 5 times.
  • Length: at most 32,768 tokens and 50 turns.
  • Exact request: the recorded conversation is exactly what was sent to the teacher.

12

Step 4: careful edits, with an audit

Many correct attempts were good except for one sentence naming a skipped item. Ali approved a small set of edit rules. Each rule only removes or narrowly corrects what the teacher's own reasoning already got right. Nothing new is invented.

Delete only

Remove words from the reply or a message; never add any. Only where the reasoning already made the right decision. The edited example must still replay to 1.0 with every check.

Verbatim value fix

For a one-check near miss, a value may be put in only if the teacher's own reasoning already decided it, copied word for word. Of 23 near misses, none qualified.

Narrow phrase fix

Swap in a phrase that appears in both the request and that turn's reasoning. Used once (a DocuSign lease email in data v4).

Masked turns

A turn stays in the conversation, so the model sees it, but it gets no training weight. Allowed only with a recorded reason: a failed call, a message whose text was deleted, or a wrong action corrected later.

The edit audit compares every row with the teacher's original attempt. A row may differ only by logged deletions and masked turns. Reasoning, requests, call names, call order and unedited tool results must be byte for byte the same. A test that tampers with rows in 4 different ways is caught every time. verified

17

What this shows, and what it doesn't

What it shows

  • SFT on correct, checked, thinking-on examples from a same-family teacher raised the 4B's test120 success from 28.3% to 42.4%, on tasks it never trained on.
  • Partial credit, harm share, tool errors and turn-limit cuts all moved the right way.
  • guard10 did not drop.
  • The spend for teacher calls stayed small: $13.64 for the 397B baselines, $27.63 for data. from record

What it doesn't show

  • One training run with one seed. How much the result moves with another seed was not measured. inference
  • guard10 is too small to measure a change either way. inference
  • The result holds for test120 at these settings (thinking on, these limits and sampling). Other settings or tests may differ. inference
  • Runaways went from 3 to 4; too few to call. inference
  • The 397B reference uses 2 attempts per task, so "two thirds of the gap" is approximate. inference

Status, 13 November 2026: the SFT measurement is done. Data v3 (97 rows) gave +14.1 points on test120. Data v4 (102 rows) is final and kept for later work without a separate run.
