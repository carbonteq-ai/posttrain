Qwen3.5-4B on AutomationBench: what was done, what to use, where it is

The goal was to make Qwen3.5-4B better at multi-step business workflows without reinforcement learning, measured on 120 AutomationBench test tasks it never trains on. Supervised fine-tuning on 97 checked examples was the main gain. One round of SDPO on its own attempts, with written feedback on its failures, added 8.2 points more and brought it level with Qwen3.5-397B. This page is about using the work: what to load, where everything is, how to run it, what to watch for. Why each step was taken is on the post-training map; results task by task are in the deep dive.

Loading them correctly

  • Base models: Qwen/Qwen3.5-4B at revision 851bf6e8, and Qwen/Qwen3.5-9B at c2022362.
  • The adapter weights are named for Qwen3.5's image-text class (Qwen3_5ForConditionalGeneration). Loaded onto the text-only class, every LoRA weight is silently skipped and you get the base model. In vLLM, use enable_lora=True with max_lora_rank=64.
  • Score them the way they were scored (why each setting: map): thinking on, temperature 1.0, top_p 0.95, top_k 20, presence_penalty 1.5, 50 turns, 32,768-token replies, a 131,072-token context, and 8 attempts per task. The 9B needs a 32 GiB KV cache; 48 GiB runs out of memory.

Run it again

Commands

  • Evaluate: scripts/qualification/sdpo_ab_launch.sh submits sdpo_ab_runner.py --phase collect to the GPU workstation through dstack (SFT README).
  • SFT and DPO: posttrain job run with the work packages in apps/lab/.posttrain/work_packages/ (SFT README, DPO README).
  • SDPO: the same launcher with --phase online-train and the arguments in the SDPO README.

Durations on one RTX PRO 6000

  • test120 read (960 attempts): 2.8 h for the 4B, 3.1 h for the 9B; guard10: 18 minutes.
  • SDPO: 2.8 h per round; a held-out read of 102 tasks: 2.4 h.
  • SFT: 21 steps of 97 rows at 32,768 tokens.

Pitfalls that cost time

  • A Qwen3.5 adapter loaded with the text-only class is silently ignored. Check that scores change with the adapter; every evaluation writes adapter-check.json.
  • posttrain job run packs the framework of the checkout that holds the posttrain command, not the current folder.
  • dstack refuses uploaded files over 2 MB. The launcher ships the environment in parts.
  • Framework jobs can hang in the tracking upload after training while holding the GPU. Cancel the run once the adapter is saved.
  • The feedback engine reads task contracts from ABCE_ENVIRONMENT. If that points at the wrong checkout, every contract is silently empty.
