## Purpose / Big Picture

After this work, a developer can select a smaller student model, a frozen
teacher model, a Verifiers environment, and separate execution bindings for
student training, student rollout generation, and teacher token scoring, then
run one reproducible on-policy distillation job. Verifiers owns the live task
interaction, tools, sandbox, verification, and native trajectory. The current
student generates every optimized trajectory, the teacher scores the exact
token IDs produced by that student, and TRL applies the distillation update.

The first supported trainer backend is the pinned CarbonTeq TRL fork. PrimeRL
is not a backend in this platform. A future `verl` adapter must be able to
consume the same backend-neutral distillation batch without changing the job's
meaning, but this plan does not add a `verl` dependency or implementation.

The feature is visible in two ways. A CPU test suite proves that an interleaved
multi-turn Verifiers trajectory keeps exact student token IDs, sampling
log-probabilities, sparse student-token loss masks, explicit prompt boundaries,
and native trace identity all the way into the TRL trainer. A credentialed GPU
smoke run then distills `Qwen/Qwen3.5-0.8B` from a frozen
`Qwen/Qwen3.5-2B` teacher on GSM8K through the existing Verifiers integration,
emits a child model artifact, and exposes distillation metrics plus the native
Verifiers traces in Observatory.

Here, on-policy means that the trajectories consumed by the optimizer were
generated by the current student weights for that training step and are
consumed once while fresh. A stored teacher completion or an old student trace
is off-policy data and belongs in supervised data generation or `train.sft`;
it must not be accepted by `train.distill`.

## Surprises & Discoveries

- Observation: The upstream-shaped TRL `DistillationTrainer` already supports
  fully on-policy generation, reverse KL, and a local or external vLLM teacher,
  but it owns student generation inside `_generate_student_completions` and has
  no external rollout hook.
  Evidence: `../trl/trl/experimental/distillation/distillation_trainer.py`
  fills its own generation buffer; by contrast, the fork's GRPO trainer already
  has a custom rollout function that can guide the new contract.

- Observation: Verifiers already supplies the hard part of the platform
  integration. `packages/train/src/posttrain/train/integrations/verifiers.py`
  produces exact multi-turn prompt/completion IDs, per-token sampling
  log-probabilities, environment masks, rewards, and native trace artifacts.
  Evidence: the existing tests named
  `test_policy_client_preserves_exact_turn_tokens_and_response`,
  `test_native_bridge_projects_multiturn_masks_rewards_and_trace_artifact`, and
  `test_trl_rollout_adapter_preserves_identity_rewards_masks_and_native_traces`
  prove these properties for GRPO.

- Observation: TRL currently derives the prompt boundary as full sequence
  length minus the number of labelled tokens. That arithmetic is invalid for a
  multi-turn trajectory because tool and environment tokens can occur after the
  initial prompt while remaining masked from the student loss.
  Evidence: `_compute_prompt_length` in the pinned fork conflates one contiguous
  prompt mask with the sparse label mask. The teacher request path can already
  accept an explicit prompt attention mask, but `compute_loss` also needs an
  explicit boundary to align teacher and student positions.

- Observation: sampling log-probabilities are required evidence of which
  student policy produced the rollout, but TRL's distillation loss does not use
  them for importance correction.
  Evidence: the current distillation loss consumes student and teacher logits
  over selected tokens, while its generation buffer assumes fresh rollouts.
  Therefore this implementation must reject replay and enforce generate-once,
  consume-once freshness instead of implying that importance sampling makes old
  traces on-policy.

- Observation: an external teacher scores the exact integer token IDs produced
  by the student. Matching model family names is not sufficient; token IDs must
  have identical meanings.
  Evidence: TRL's `get_sequence_logprobs` request sends existing sequences, not
  teacher-retokenized text. The real integration must prove matching tokenizer
  vocabulary size and token-to-ID mapping before training begins.

- Observation: the main repository is currently dirty, while `../trl` is clean
  on `codex/grpo-rollout-inputs` at
  `83ce4962aff9f72edf97c034f56e25d2f52553f7`. The main repository pins the
  later merge commit `a0b4bca78eeeb02abb050abfa04624f952d5f633`.
  Evidence: `git status --short`, `git -C ../trl status --short`,
  `packages/train/pyproject.toml`, and `uv.lock` inspected on 2026-07-22.

- Observation: preserving structured prompt messages in every distillation

  object has no attribute 'to'` failures. Restricting message preservation to

- Observation: Verifiers must call the current student one turn at a time and

## Decision Log

- Decision: Define `train.distill` as fully on-policy student distillation,
  with no mixed off-policy mode in the first platform contract.
  Rationale: a narrow job meaning is reproducible and prevents stored teacher
  traces from being mislabeled as on-policy. TRL's internal `lmbda` must be
  fixed to `1.0` by this adapter. Off-policy teacher traces remain valid inputs
  to `train.sft` or a separate future technique.
  Date/Author: 2026-07-22 / user and Codex.

- Decision: Use Verifiers as the environment and live rollout layer, not as a
  reward wrapper around TRL GRPO.
  Rationale: distillation optimizes teacher/student token-distribution
  divergence, not a scalar reward objective. Routing it through GRPO would
  corrupt algorithm semantics and hide teacher scoring behind a reward hack.
  Date/Author: 2026-07-22 / user and Codex.

- Decision: Support the CarbonTeq TRL fork first; do not integrate PrimeRL.
  Preserve a backend-neutral batch seam for a future `verl` adapter without
  adding speculative abstractions or dependencies for it now.
  Rationale: the user selected TRL now and `verl` later. PrimeRL is useful
  research evidence for Verifiers integration but is not a platform contract.
  Date/Author: 2026-07-22 / user.

- Decision: The first loss is sampled-token, top-1 reverse KL through an
  external teacher server. Expose temperature and the existing TRL generalized
  divergence parameters in the backend adapter only where they preserve the
  canonical algorithm meaning; reject unsupported combinations in preflight.
  Rationale: reverse KL on student-generated tokens matches the intended
  on-policy distillation path and lets the teacher server return compact
  per-token scores. The platform can add a deliberate forward-KL or wider top-k
  contract later without pretending all variants have identical cost and
  semantics.
  Date/Author: 2026-07-22 / Codex.

- Decision: Generalize `OnlineRLBridge` to `EnvironmentRolloutBridge`, and
  generalize `TrainingRollout` to `EnvironmentRollout`, because Verifiers
  trajectories are consumed by both GRPO and distillation. Keep a deprecated
  import alias for one compatibility window only if an external caller requires
  it; migrate all in-repository callers in the same change.
  Rationale: environment execution is reusable capability; “RL” and “reward”
  are consumer interpretations. Long-term names must not make distillation look
  like an RL special case.
  Date/Author: 2026-07-22 / Codex.

- Decision: Keep Verifiers native traces as replay authority and add no second
  distillation trace format. Preserve the teacher and student selections plus
  optimizer metrics as run evidence around those traces.
  Rationale: copying trajectories into a trainer-owned format would split trace
  identity and make replay ambiguous.
  Date/Author: 2026-07-22 / Codex.

- Decision: Amend `docs/post-training/02-primitives.md`,
  `04-framework.md`, `05-apis.md`, and `06-observation-and-lineage.md`, with a
  concise amendment entry in `README.md`. Do not change
  `03-work-and-evidence.md` unless implementation proves that its existing
  hierarchy cannot express the new job.
  Rationale: the change adds a technique, selections, API, ownership, and
  evidence, but it does not alter project, work-package, job, or run identity.
  Date/Author: 2026-07-22 / Codex.

## Context and Orientation

This is a Python 3.12 `uv` workspace. `packages/common` owns backend-neutral
selections and identities. `packages/train` owns reusable training contracts
and private trainer adapters. `packages/data` owns datasets, including rollout
datasets. `packages/eval` and the Verifiers dependency own environment and
evaluation semantics. `apps/lab` composes concrete work packages and wires
observation. `apps/observatory` reads normalized run evidence. Reusable train,
eval, and serve packages must not import one another, and none may import
`apps/lab`.

An `InferenceBinding` in
`packages/common/src/posttrain/common/selections.py` selects a model variant,
renderer, inference backend, sampling settings, engine settings, execution
target, and declared purpose. Add `teacher-score` to its allowed purposes. The
student rollout binding continues to declare `rollout`; the teacher scoring
binding declares `teacher-score`. These bindings may use execution targets
different from the student's training target.

An environment rollout is the exact token-in/token-out trajectory returned by
Verifiers. It contains the initial prompt token IDs, completion token IDs across
all turns, the sampling log-probability recorded when each token was generated,
a Boolean mask that is true only for student-generated tokens, environment
outcomes used as trace evidence, and a native Verifiers trace. Distillation uses
the Boolean mask as a sparse loss mask. It does not optimize Verifiers reward;
the reward remains environment evidence and a useful evaluation measure.

A distillation batch is the backend-neutral handoff from live environment
execution to a trainer adapter. It contains only fresh rollouts, a unique policy
revision or training-step identity, and a consume-once batch identity. The TRL
adapter translates this batch into the fork's external rollout hook. A future
`verl` adapter should translate the same values into `verl` without changing
the public request or Verifiers bridge.

The current public train surface is in
`packages/train/src/posttrain/train/api.py`, `requests.py`, `profiles.py`, and
`catalog_schema.py`. `online_rl.py` contains the reusable policy-generation and
rollout types. `integrations/verifiers.py` implements the Verifiers bridge.
`backends/trl/grpo.py` and `backends/trl/online_rl.py` show how the fork's GRPO
rollout hook is wired. Tests live in `packages/train/tests`.

The concrete host is under `apps/lab/src/posttrain_lab`. Work-package job
definitions are in `work_packages/definitions.py`; execution and catalog value
serialization are in `work_packages/runner.py`; GSM8K composition is in
`jobs/gsm8k_posttraining.py`; the user entry point is `cli.py`. Catalog
selections are under `packages/catalog/src/posttrain/catalog/base`, and
project-local work packages are under
`work_packages`.

The sibling `../trl` repository is the CarbonTeq fork. The executable authority
for its revision is `packages/train/pyproject.toml` plus `uv.lock`, both of which
currently select
`9c01e51243aed3c88d1f726bd6dab59843b62a9b`. The distillation implementation is
under `../trl/trl/experimental/distillation`; its focused tests are
`../trl/tests/experimental/test_distillation_trainer.py`. Make the generic
external-rollout improvement there, commit it independently, and only then pin
that immutable commit here.

## Interfaces and Dependencies

The final public train package must export `OnPolicyDistillationSettings`,
`OnPolicyDistillationRequest`, `DistillationBatch`,
`DistillationBatchSource`, and the `distill(...)` operation. The exact async or
sync shape of `distill(...)` must match the existing public operations in
`packages/train/src/posttrain/train/api.py`; do not introduce a second lifecycle
style. Its result must use the existing `ProducedArtifact`, metrics, and run
context conventions.

`EnvironmentRolloutBridge` remains backend-neutral and depends only on common
and data contracts. It must not import TRL, Verifiers implementation classes,
Trackio, W&B, `apps/lab`, or Observatory. The Verifiers adapter remains under
`packages/train/integrations`; the TRL translation remains under
`packages/train/backends/trl`. Train, eval, and serve packages must not import
one another.

`InferenceBinding.purpose` gains the literal `teacher-score`. A teacher scoring
binding selects the immutable teacher `ModelVariant`, its renderer/tokenizer
contract, a versioned vLLM backend, engine configuration including service
address or resolvable endpoint, and an `ExecutionTarget`. Secret credentials,
if a remote endpoint is later used, come from runtime configuration and never
from catalog YAML.

The TRL dependency remains the CarbonTeq fork and must use one immutable commit.
The fork change is generic: its external rollout hook speaks token IDs, masks,
log-probabilities, and metadata and contains no `posttrain` or Verifiers imports.
The main adapter fixes TRL `lmbda=1.0`, `beta=1.0`, sampled-token top-1 teacher
scoring, and external teacher mode for this first product contract.

Verifiers remains the authority for dataset/task interaction, tools, sandbox,
verification, environment outcome, and native trace. The platform may project
those values into a `DistillationBatch` for live consumption, but it must not
persist a competing trainer-native trajectory as replay authority. PrimeRL is
not added. `verl` is named only as the next adapter target and must not affect
this release's dependency graph or acceptance criteria.
