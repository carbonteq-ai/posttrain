# VORTEX next: adaptive variance curriculum

## Decision and example

Keep two sampling lanes, 80% and 20%. Both may choose any task. The normal lane favors a task whose recent groups repeatedly show meaningful reward differences. The exploratory lane uses the same estimate and adds a bonus for uncertain or stale evidence. This is a sampling bias rather than a quota for new tasks. With no observations, each AutomationBench class has equal weight and each task within its class has equal weight. If all tasks are well measured, the bonus becomes small and both lanes choose similarly.

For example, suppose four rollouts score `[0.0, 0.0, 0.2, 0.2]`. The mean reward is low, but the group contains a signal that can distinguish trajectories. A group scoring `[1, 1, 1, 1]` has reached a maximum and has no group-relative difference; `[0, 0, 0, 0]` also has none. Both constant patterns lose normal-lane weight after repeated observations, but the report keeps them separate: one suggests mastery, the other current difficulty. As policy steps pass, their old evidence loses weight, allowing a recheck through the exploratory lane. A single high-variance group does not outrank a task that has shown useful variation consistently across many groups.

## Selection contract

The input is a finite task inventory with a class for each task and four normalized scalar rewards for every observed group. A valid observation has four finite rewards in `[0,1]`. At optimizer step `t`, let `v` be the population variance of the four rewards and define a bounded magnitude signal `y = v / (v + s²)`, where research scale `s = 0.1`. This distinguishes tiny gaps from substantive gaps without letting a single extreme value dominate numerically. The scale is a research hypothesis that must be calibrated to the actual reward's resolution and judge noise; it is not yet a product default. A binary `v > 0` version remains an ablation.

For each task, keep an effective observation count, a sum of `y`, and a sum of `y²`, all down-weighted by `2^(-Δstep / H)` as the policy changes. Research half-life `H = 20` optimizer steps is a sensitivity parameter. For an unseen task, use evidence from peer tasks in its class, with a common uniform prior. For a seen task, blend its own moments with the class estimate. Each peer task contributes at most one unit to the class aggregate, preventing a heavily repeated task from owning the class prior. Omit the candidate task from its own class prior to prevent double counting.

Let `m` be the resulting mean bounded magnitude, `b` its between-group variance, and `n` the task's effective observation count. The prototype assigns `normal = m / (1 + 4b)` and `uncertainty = sqrt(b / (n + 1))`. The 80% lane samples with weight `normal`; the 20% lane samples with weight `normal + uncertainty`. These terms are nonnegative. Class weights are the *average* candidate-task weight within each class, then task weights are normalized within the selected class. This preserves equal cold-start class weight even when class sizes differ. Once a task's effective evidence ages, its uncertainty increases toward the class prior and it can be rechecked. After every candidate batch, observations update both lanes; no rewards from the same batch are visible while selecting that batch.

The reward mean is a diagnostic, not a multiplier in the sampling score. A lower-reward task can remain attractive when its groups repeatedly have meaningful variance. Report constant maximum-reward and constant low-reward groups separately. The admission contract remains the existing group-variance rule during this research experiment, so the new selector changes which tasks are proposed but not which four-rollout groups count as usable. Runtime errors, missing scores, incomplete groups, and the actual trainer's truncation policy need explicit production qualification.

## What the simulation can establish

The [numeric snapshot](./simulations/vortex_next_groups.json) contains four scalar rewards, task/class identity, step, tokens, truncation/error counts, and run provenance for seven retained AutomationBench runs. The [offline prototype](./simulations/vortex_next.py) runs 100-step paired replays with eight required useful groups per step and at most four rounds, comparing a class-balanced uniform sampler, the actual current controller, a binary-score two-lane version, a magnitude-only two-lane version, and VORTEX next. This isolates whether magnitude, stability, and aging improve candidate-group use and task coverage. A second scenario forces one deterministic task cohort to become constant at maximum reward after step 40 and another to recover variance after step 60; this stress test checks response to policy drift and is an explicit synthetic assumption.

The source traces contain only tasks historical samplers chose. For unobserved outcomes, the replay samples from that task's empirical groups and from class peers with a fixed shrinkage strength. All compared policies see the same deterministic draw for a given task visit and seed. This supports paired comparisons of selector mechanics; it cannot establish counterfactual training gains, gradient quality, or GPU-time savings. VORTEX next is ready for a shadow test only if it reduces candidate groups per retained group without collapsing class coverage, avoids repeated maximum-reward/low-reward constant groups, and responds to the synthetic saturation/recovery phases. A live same-checkpoint comparison must then measure held-out gain per GPU-hour, policy stability, and real sampling time.

The seven source runs all name `LiquidAI/LFM2.5-2.6B` at model revision `654f9463ce32b05d0429d76fe1f580b27d4c1ac0`, but they use different environment revisions and training settings; they remain separate replay scenarios. Across the source groups, 2,028 complete groups were available in the earlier snapshot, and the new snapshot includes 2,072 complete groups because the current VORTEX run grew. For VORTEX v3 in the new snapshot, 130 of 210 groups have nonzero variance, but only 79 reach variance `0.01` or above. This spread makes variance magnitude a material ablation. These counts are source descriptions, not cross-run treatment effects.

The [paired simulation report](./simulations/vortex-next-analysis.md) now shows that the routing contract works but this particular scoring rule underperforms the current controller. The proposal is therefore a tested research candidate, **not a recommended production replacement**. The next iteration should keep the controller's useful-group probability as its primary score, retain both soft full-pool lanes, and treat magnitude/stability as diagnostics until a stronger live signal justifies them.

That simpler iteration has now been [replayed separately](./simulations/vortex-simple-analysis.md). It improves admitted-group efficiency but narrows task coverage; stronger soft exploration recovers much of that coverage at a measurable efficiency cost. The retained VORTEX profile uses **unscaled** centered advantages, so raw reward variance remains a relevant update-strength proxy even though binary admission is the immediate refill rule. No task is duplicated within a simulated optimizer step; production's exhausted-inventory duplicate fallback remains a release gate.
