# Acceptance cohort 03

This is a new ten-task authoring batch drawn from the already reviewed 105-task development selection. It is disjoint from cohorts 01 and 02 and spans six domains. It leaves the separate requirement of at least 15 qualified tasks per domain intact. No catalog entry, published count, source package or prior cohort is changed.

All ten draft manifests compile and bind the complete public prompt and initial state. Each includes the applicable summary and no-clarification policy declarations. The latter uses `no_clarification@2`, which adds the reviewed communication-basis boundary; its semantic acceptance is still pending. Pinned assessor identities and a compiler pass do not establish model accuracy or task completion.

Four drafts also include five acknowledged Slack destination-occurrence diagnostics: finance alerts, both escalation channels, facilities incidents and engineering. The current schema uses the goal role for these occurrence checks, but this authoring index explicitly classifies them as incomplete diagnostics. A message such as “Ignore the invoice; nothing was reconciled” or “Escalation canceled” can satisfy a destination check. These checks establish neither the requested report nor its purpose, facts, counts, prerequisites or cross-artifact references. Every credit array is empty. No destination-only send earns reward.

The current reusable Jira creation/status/retention, Slack send, Gmail read/send and initial/final record capabilities are reflected in the gaps, rather than repeating obsolete blanket unsupported labels. Important gaps remain: full invoice joins and correction authority; QuickBooks terms; BambooHR effective-dated employee updates; exact equipment sets and IT audience; Mailchimp archive state; Salesforce Contact creation and Account/Case relationships; Confluence pages; Twilio SMS; generated Gmail label membership; and HelpScout tag/note-to-Jira-key linkage. HubSpot evidence is a different service and cannot stand in for Salesforce.

The index separates public goals, prohibitions, constraints, unresolved interpretations, supported components and future action-credit requirements for every task. Exact entity IDs copied from public directories are observations, not hidden expected-answer lists. Approximate tool-budget guidance is recorded without inventing a hard 50-turn cutoff. No home shipping address, undisclosed salary announcement, arbitrary message template, severity tie-break or maximum-ARR ranking is added.

Independent review found an additional explicit process requirement for email blast suppression: public `compliance_1` says to read all six SOP sections before processing any bounce cleanup. The current policy-only proposal does not prove full-section observation or read-before-archive ordering. These are uncovered requirements, including the adverse case of an otherwise eligible archive performed too early.
