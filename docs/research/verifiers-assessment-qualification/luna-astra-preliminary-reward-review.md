## Implementable deterministic rule set

Version each task-family rule against the public policy/source snapshot. Use decimal monetary arithmetic, declared simulated time, stable employee identity, and all recipient fields. Extract known structured fixture clauses into reviewed typed policy facts; do not claim a universal parser for arbitrary natural-language policy.

1. **Goal obligations:** keyed tuples `(entity, effect-kind, target, policy-revision)`. A send goal requires a retained created/sent artifact with correct entity, values, recipient and content purpose. A tracker goal requires correct row/worksheet and applied value. NDA status additionally requires a matching prior successful sent envelope. Permit any equivalent discovery path and grouping of notifications that the policy permits. Count one accomplishment per obligation, not every overlapping name/amount assertion.
2. **Prerequisite evidence:** mark a required fact available when it is actually returned to the solver, with result reference and scope. Empty searches and tool-schema discovery are not retrieval of policy. Repeated reads do not repeat acquisition credit; amended evidence can establish a new fact revision. This proves availability, not cognitive use or causal necessity. Prefer diagnostics initially; calibrate any shaping before admission.
3. **Transient guards:** examine each applied write or sent artifact against policy before that action. Offboarding future threshold is strictly more than 14 days; involuntary public Slack prohibition covers every public channel. Referral eligibility uses hire-date +90 days, Paid/void/termination exclusions and exec hold; forbid finance recipients. Bonus payout checks cap and PIP, while salary mutation and disclosure are separate predicates. Do not declare universal guard pass when a service's event coverage is missing.
4. **State progress:** retain terminal satisfaction and transition deltas separately. A wrong write followed by repair restores the terminal goal but retains the earlier violation. An A→B→A→B loop cannot harvest repeated positive reward: maintain obligation identity and explicit reversal/debt, or grant a single terminal accomplishment with local evidence. Durable sends cannot be undone by a corrected row or later email.
5. **Partial credit:** independent completed obligations can earn credit while missing obligations and harm remain visible. No universal weighted sum is proposed here. Avoid multiple rewards for the same email's name, amount and delivery. A conservative eligibility reducer requires all required goals, all required guards assessed and satisfied, valid execution/finalization, and qualified budget evidence. The official scalar is immutable and separate.
6. **Costs:** count execution attempts, successful domain effects, failed domain returns, SDK retries and discovery separately. Enable efficiency comparisons only after that eligibility gate. Hosted completed-response IDs and reported usage exist; reconciled reporting is useful but is not original-token alignment or completeness of failed streams. Do not set budgets to Luna's shortest observed path, or infer assistant-turn count from receipt count.

Semantic notification content that cannot be safely parsed should be unavailable for the deterministic predicate, or go to a separately identified judge—not silently pass or fail. For these concrete structured amounts and receipts, deterministic checks can establish target/value/state facts; nuanced intent and acceptable phrasing may need a judge with explicit evidence limits.

## API recommendation and architectural critique

The existing assessment → domain assignment → projection separation is appropriate across deterministic, judge and hybrid producers. One reusable envelope is enough; do not add an AutomationBench reward transport or require deterministic rules to inherit a chat judge. Keep task rules ordinary versioned Python. Runtime builders should supply provenance so authors write predicates rather than hashes.

The material missing subject is an **execution occurrence**. Current `SubjectRef(kind="call")` requires a native sampled node digest and original generated-attempt ordinal. The retained invocation UUID is not that identity. Add a narrowly typed source-bound reference, usable as a subject and assignment recipient:

```text
ExecutionOccurrenceRef:
  snapshot_id, episode_id, trace_id
  execution_source_id / ledger_digest
  invocation_id, occurrence_digest
```

The referenced source member holds dispatch/result phases, their digests, arguments, state revision/conflict information and environment evidence. Keep observation phase/cutoff in the view: a dispatch-only prefix must not read a later returned receipt. A snapshot extension may explicitly resolve the same immutable occurrence into a new reference; silently retargeting old findings is invalid. The digest must bind lifecycle evidence available in that snapshot, not only an unscoped UUID. Reject unresolved, duplicate or cross-snapshot references. Multiple execution retries may eventually link to one generated call via a separate qualified mapping; never collapse them by equal JSON or provider ID.

Assignments to these recipients are meaningful for evaluation now. Projection returns unsupported until a proven occurrence→generated-attempt→original sampled-token relation exists. Native SDK rawResponse/completed metadata supplies response IDs and reported usage; it does not establish original graph nodes, prompt/output token coordinates, failed-stream completeness, or that relation. Do not fabricate turn numbers, spans or masks. Until the new subject is implemented, attach trace-level findings with exact receipt evidence and unavailable local alignment.

Add a read-only evidence-view builder that resolves source snapshots, results, state acknowledgements and coverage. A return with `success:false` remains an observed result; a missing acknowledgement is unavailable transition attribution. Receipt order alone is not serialization of concurrent effects. Joint/conflicted transitions need grouped recipients or unavailable attribution, not duplicated full credit.

For hybrid assessment, preserve independent deterministic facts and model opinions. A judge may assess notification meaning using the declared policy and exact sent body; its finding is not independently corroborated when it was prompted with deterministic labels. A versioned derived rule may combine them and must retain parents, gates and validity propagation. Optional judge failure must not invalidate an independently verified finance-CC violation; missing required semantic interpretation must not become zero. Do not resolve conflicting producers by averaging probabilities with progress or taking the last result.
