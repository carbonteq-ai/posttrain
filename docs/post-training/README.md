# Post-training docs (canonical baseline)

**Status: FROZEN — 2026-07-21** (implementation checkpoint)
**Amendment — training decoupling:** `TrainingBinding`, `ParameterUpdatePlan`,
`QuantizationPlan`; algorithm settings must not own rollout engines or mandatory
QLoRA; train≠rollout targets allowed; async RL deferred. Details:
[02 · Training](./02-primitives.md#training-selection), plan
[slice 3a](../../.agents/plan/baseline-implementation.md).
**Amendment — tracking backends and job-aware views (2026-07-22):** the
framework owns the logical run, metric, event, trace, artifact, and outcome
contracts; Trackio and W&B are backend adapters. Trackio remains the default
local backend. One job-telemetry definition drives normalized Python, frontend,
and MCP views. Details: [04 · Framework](./04-framework.md),
[05 · APIs](./05-apis.md), [06 · Observation](./06-observation-and-lineage.md),
and the [implementation plan](../plan/dual-backend-tracking-observatory.md).
**Amendment — Verifiers-driven on-policy distillation (2026-07-22):**
`train.distill` consumes fresh trajectories generated by the current student
through a Verifiers environment and teacher scores over those exact token ids.
TRL is the first trainer adapter; PrimeRL is not a supported backend, and a
future verl adapter must preserve the same job meaning. Details:
[02 · Primitives](./02-primitives.md#training-selection),
[04 · Framework](./04-framework.md), [05 · APIs](./05-apis.md),
[06 · Observation](./06-observation-and-lineage.md), and the
[implementation plan](../plan/verifiers-on-policy-distillation.md).
**Amendment — environment-only GRPO (2026-07-23):** `train.grpo` binds one
versioned Verifiers `EnvironmentBinding`, not a dataset or hand-authored task-id
selection. The environment binding may select task categories and bounded
sampling policy; concrete task identities are resolved inside the environment
and retained in Verifiers traces for replay. Dataset seats remain the public
input for supervised and preference training. Details:
[02 · Primitives](./02-primitives.md#training-selection),
[05 · APIs](./05-apis.md), and the
[GRPO implementation plan](../plan/grpo-research-observability.md).
**Amendment — portable project layout and catalog distribution (2026-07-23):**
tracked project overlays and work packages live under `.posttrain/`, ignored
runtime state lives under `.posttrain/state/`, and the framework base catalog
is a versioned `posttrain-catalog` package resource. Durable artifacts remain
tracking/artifact-backend values rather than project-directory lineage.
Details: [04 · Framework](./04-framework.md), [05 · APIs](./05-apis.md),
[ADR 0013](../decisions/0013-portable-project-layout.md), and the
[implementation plan](../plan/portable-project-layout-and-consumer.md).
**Amendment — primary CLI and release boundary (2026-07-23):** the `posttrain`
distribution provides the stable project, catalog, diagnostic, and
work-package command surface. `apps/lab` remains a reference composition host,
not the required consumer entry point. Public package and OCI registries may be
used to distribute polished releases to CarbonTeq-managed projects and remote
servers. Generic recipe/work-package contracts, resolution, validation, and
execution helpers live in `posttrain.work`; concrete first-party job
definitions and provider wiring are supplied by a host. Details:
[04 · Framework](./04-framework.md),
[05 · APIs](./05-apis.md), and the
[release implementation plan](../plan/polished-framework-release.md).

## Freeze contents (this checkpoint)

Locked in at freeze time:

- Stages: `screen` \| `train` \| `qualify` (selection is not a stage)
- Ontology: Project → Work package → Run of a Job
- Primitives + catalog base/overlay; `CatalogRef` → selection
- Model variant (incl. weight quant) vs inference binding (`engine` field) vs target
- Operations = job kinds (`train.sft`, `train.distill`, `eval.domain`, …);
  `RunContext`
- Eval: Verifiers traces = authority; plans compose cells; no parallel score DB
- Observation: group ≈ `work_package_id`; metric namespaces in 06
- Tracking: framework-owned logical evidence; Trackio and W&B adapters;
  job-aware views shared by Python, frontend, and MCP

## Canonical vocabulary

| Prefer | Avoid (legacy) |
| --- | --- |
| work package | job-as-grouping / experiment |
| job kind / job definition | “job” as the grouping noun |
| operation (`train.sft(…)`) | “Job API” as a separate layer name |
| selection (`ModelVariant`, …) | `ModelRef` / profile for the same value |
| `CatalogRef` → resolve → selection | dual lookup / parallel ref types per family |
| `RunContext` | Trackio-coupled execution object |
| model variant (incl. AWQ/Q4 weights) | “Q4 inference profile” for on-disk quant |
| inference binding | serve / inference profile |
| `InferenceBinding.engine` | separate EngineProfile catalog type |
| `TrainingBinding` + `ParameterUpdatePlan` | QLoRA baked into every `*Settings` |
| `QuantizationPlan` | ad-hoc quant dicts / recipe paths only on call sites |
| algorithm settings vs train/rollout bindings | mega-`GRPOSettings` owning vLLM topology |
| execution target | hardware profile (alias OK in catalog ids) |
| evaluation plan | Verifiers “suite” type / eval suite baked with a model id |
| native Verifiers traces as eval authority | parallel score DB that replaces `traces.jsonl` |
| catalog base + overlay | dual catalogs / copy-paste engine YAML |
| `work_package_id` (tracking group) | Provider group = old `job_id` alone |
| `.posttrain/work_packages/` (project dir) | `packages/` for YAML work-package configs |
| async RL (deferred) | calling Trackio/background I/O “async RL” |
